Implicit Surfaces (Ray Marching)

← Geodesic Flow & Non-Euclidean Geometries  ·  Contents  ·  Rendering & Textures →

In addition to parametric surfaces, Surface Explorer 4D supports Implicit Surfaces defined by mathematical equations in the form of f(x, y, z) = 0 (e.g., x^2 + y^2 + z^2 = 1). These are rendered using an advanced graphics technique called Ray Marching.

 

How it Works

Instead of generating a grid of polygons (vertices and faces) on the CPU, the Ray Marching engine shoots rays from the virtual camera into the 3D space to find the exact point where the mathematical formula equals zero. This allows for mathematically perfect curves, infinite repeating structures, and complex boolean operations (additions, subtractions, and intersections of shapes) that would be impossible with standard geometry.

 

Key Settings

  • Equation: The main formula. Use the variables x, y, z. Example: x^2 + y^2 + z^2 - 1.0 = 0.0 (the = 0.0 part is handled automatically if you omit it).
  • Displacement / Variations: You can inject GLSL code here to distort the space or add bumps to the surface before it is evaluated.
  • Ray Steps: Defines the maximum number of steps a ray can take to find the surface. Higher values (e.g., 200-500) improve rendering accuracy but reduce performance (framerate).
  • Step Relax (S): A safety multiplier for the ray step size. If you see visual artifacts, "holes," or ghosting on highly distorted or fractal shapes, lower this value (e.g., to 0.4 or 0.2) to force the rays to advance more cautiously.
  • Spatial Limits (Bounding Box): Since implicit surfaces can easily extend to infinity, you can set X, Y, and Z Min/Max values to cut the shape inside an invisible bounding box. The limits follow the same rule as the equation: on a still surface they are applied when you press Run, so you can fill in all six fields and see the result once; while the surface is animating there is no Run to press — the button reads Stop — so pressing Enter in a field applies it straight away, without interrupting the motion.
  • Constant sliders (A–F): Name a constant anywhere in the equation, in 3D Variation or in Texture Code and its slider unlocks by itself, ready to reshape or recolor the object live. When you save, the app offers a short hint — a message shown over the scene on loading — which is where to say what each slider actually does (Slider F: relief density). Textures written in the Shadertoy form (mainImage()) are the one place the constants cannot be reached; see the Scripting Guide.
  • Solid vs Shell: Solid mode fills the inside of the object, while Shell mode renders it as a hollow, infinitely thin surface.

Troubleshooting Visual Artifacts

When exploring arbitrary implicit equations, you might encounter visual artifacts such as infinite "blades", floating planes, or holes in the geometry. This happens because some mathematical functions grow too fast, causing the ray to "overshoot" and completely jump past the surface.

The Scale Factor Trick (0.1 Multiplier)

If your surface looks broken or has external artifacts, the standard mathematical practice is to multiply the entire equation by a small scale factor (Lipschitz bound).

Example: Change x^2 + y^2 + z^2 + 2*x*y*z - 1.0 to 0.1 * (x^2 + y^2 + z^2 + 2*x*y*z - 1.0).

This artificially reduces the steepness of the function, forcing the ray to take smaller, safer steps without altering the actual shape of your object.

Shell vs. Solid Stability: These artifacts are especially prominent in Shell mode. Because the shell has a fixed, microscopic thickness, a fast-traveling ray can easily jump right through it without detecting a hit. If you don't specifically need the hollow shell effect, switching to Solid mode provides a much more robust and stable rendering. If you must use Shell mode, using the 0.1 multiplier or lowering the Step Relax (S) slider is highly recommended.

Limitations: Because Ray Marching does not use traditional polygons, the Wireframe rendering mode is disabled. Additionally, implicit surfaces in this software are strictly evaluated in 3D space (X, Y, Z); therefore, 4D hyperspatial rotations (Omega, Phi, Psi) and the P coordinate are not applicable.
