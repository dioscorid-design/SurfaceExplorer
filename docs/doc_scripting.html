Script Dock & Advanced Scripting

For expert users, the Script dock provides a powerful GLSL code editor to bypass the standard equations and directly program the GPU for surfaces, textures, and sounds.

 

Script Buttons

The Script dock features several action buttons to compile and apply your code depending on your current goal:

  • Run Script: Compiles the code to define the geometry of a surface. The engine intelligently detects the script's nature: it can handle Parametric surfaces (using u, v, w) or Implicit surfaces for Ray Marching (using x, y, z and distance functions). Special configuration variables like u_min, A, B can be declared at the top to seed the matching UI fields and sliders. These directives act as defaults: they only fill in values that have not yet been set in the dock—they never overwrite a value you already entered there. (The steps directive is the exception: it is not applied at all — resolution is always driven by the Steps slider.) See Geodesic Flow for the precedence rule when a surface is driven by both the script and the Equations dock.
  • Apply Texture Script: Applies the GLSL code as a procedural texture. It will be mapped onto the 3D surface or the 2D background, depending on which target is currently active in the Renderer dock.
  • Run Sound / Stop Sound: Parses the script for //SYNTH: or //MUSIC: directives and executes the audio engine. The button toggles to "Stop Sound" during playback and can be clicked again to halt the audio.
  • Save Script: Prompts you to save the current editor content as a new Surface, Texture, or Sound preset in your Library.

 

One surface, one dock

A surface whose shape is defined by a script is defined either there or in the Equations dock — not by both at once. The two are alternative sources for the same geometry, and this holds in Ray Marching exactly as it does for parametric surfaces: an implicit surface can come from the Equation field or from a script returning a distance function, but only one of them is in force.

So if the surface on screen comes from one dock and you start typing in the other, the two do not combine: what you type may not take effect, or may mix with the state already loaded. The application says so with a message the first time you do it. To work from a clean state you have two options: click the tab of the current mode (Parametric or Implicit) to clear everything and get the default surface back, or press NEW on the status bar to clear everything and leave the scene empty. Either way both docks are free again and you can write wherever you prefer.

Metric-tensor scripts are the exception, and an important one. A script ending in return mat3(...) does not describe a shape: it defines the metric gij, while the chart and the initial conditions of the geodesic flow live in the Equations dock. The two panels are not competing there — they describe one geometry together, which is why the presets in Black Hole and several Rotations records fill both. Loading one of them raises no warning. If you then write into either dock the message can still appear, because from a blank editor the application cannot tell whether you are extending the metric or starting an ordinary surface; it is only a reminder, and you can carry on. The rule deciding which panel wins when the two disagree is in Geodesic Flow.

 

Script Language Reference

Scripts are GLSL code pre-processed by the application's internal translator, which adds math shorthand (^ powers, % modulo, pi/tau constants), UI directives (u_min := -3.0;) and a few strict rules (such as automatic integer-to-float conversion). For the complete syntax, available variables, helper functions and examples, read the dedicated guide: GLSL Script Writing Guide.
